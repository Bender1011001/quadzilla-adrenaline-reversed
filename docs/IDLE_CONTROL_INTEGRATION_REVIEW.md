# Original idle gate, accumulator and caller integration

This pass composes the previously modeled selector, input gate and fresh
accumulator inside **150 complete original `0x50F0` calls**. It uses the exact
32,000-byte V2.8.4HF image, SHA-256
`1ae519ba6194e8f7bdaaa94333a83a9e6fda3b0563f87f7d48383b37288c1780`.
The [artifact](../audit/data/idle_control_integration.json) retains 144 isolated
cases and three persistent two-call sequences. No helper return is stubbed.

## Why the entry active flag did not work

The [retention-branch suite](CONTROL_RETENTION_BRANCH_REVIEW.md) supplied
`0x20042D` at entry but did not reach `0x52F0`. The control routine calls
selector `0x506C` at `0x5236` and immediately passes its returned mode to gate
`0x4818` at `0x523C`. That gate writes `0x20042D` on every return path.
The earlier suite disabled it through `0x2006E2=0`, and its nonzero selector
also inhibited progression. Thus the entry override was overwritten before
the later branch. This is an original-call ordering explanation, not a claim
that every other writer has been excluded.

The new matrix enables the gate and varies initial states 0/1/3, working
selector 0/5, capture 999/1200, completion event 0/1, fresh flag 0/1 and
old accumulator 0/649/`0xFFFFFFFF`. Source word `0x2005F0` and input byte
`0x2005D7` are zero. Duration is 2. Timer and retained flag sentinels are
explicitly seeded to the existing gate model's values in the reproducer.
All 144 gate results and side effects match that independent local model.

Exactly 24 cases return active, all with initial state 3 and selector zero.
In those cases `0x52F0..0x5308` executes the original accumulator helper
`0x48E8`. All accumulator results, previous-delta stores and three flag bytes
match the existing wrapping/signed-division model. Original scalar, table,
timer-admission, stack and preserved-register checks also run.

## Persistent transition and delayed consumption

Three sequences start in state 1 with completion event 1, capture 999,
selector/source/input zero, fresh flag zero and old accumulator respectively
0, 649 and `0xFFFFFFFF`. The first whole call advances state to 3 and sets
fresh to 1, but returns inactive. Consequently the accumulator is not called.

The next whole call uses the retained SRAM without any harness writes between
calls. Only the host call's SP/LR convention is re-established. State 3 returns
active, the accumulator runs, and fresh becomes zero. Its fresh delta is 201;
the signed quotient is 5. Results are respectively **206, 650 and 205**.
The last case wraps `0xFFFFFFFF + 5 + 201` before the helper's sign/clamp tests.
The 650 result is the helper ceiling. Both calls execute original code;
completion events are supplied at sequence entry, not generated by a modeled
TC2 interrupt or measured delay. The earlier callback review remains separate.

## Stale storage and caller saturation

A stale accumulator returns its old value without the fresh 0..650 clamp.
Four isolated cases retain `0xFFFFFFFF`. The caller then adds its capture-side
base with 32-bit wrap at `0x5308`, checks unsigned against 4096, and stores
at most 4095 to `0x200600`. In these four cases the base is zero, the addition
remains `0xFFFFFFFF`, and the caller stores 4095. This establishes different
helper and caller bounds; it does not establish that such stale storage occurs
in normal service. The harness checks both the addition and actual caller store.

## Coverage, reproduction and remaining work

Thirteen additional main starts execute, including the caller saturation
instruction at `0x5310`. Union with the initial scalar-integration and retained
sample suites is **520/574**, leaving 54 listed starts. This is a three-suite
instruction union, not exhaustive branch or path coverage.

Controlled initialized SRAM, supplied state/event flags and functional peripheral
memory do not prove live state admission, asynchronous ordering, hardware timing
or output effects. The setup call at count 2001, optional timer upper clamp,
global writer bounds and other main branches remain open. Response instructions
execute but their arithmetic is not independently checked in this extension.
The full firmware goal remains active.
