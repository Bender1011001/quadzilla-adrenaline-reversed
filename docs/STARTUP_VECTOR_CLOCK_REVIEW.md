# Startup vectors, memory setup, and clock configuration

This review concerns the exact 32,000-byte V2.8.4HF application image,
SHA-256 `1ae519ba6194e8f7bdaaa94333a83a9e6fda3b0563f87f7d48383b37288c1780`.
Evidence is the [bounded explicit-ISA decode](../audit/data/startup_persistence_binaryninja.json),
the [byte-verified IDA items](../audit/data/ida_image_items.json), and a
[synthetic SRAM/MMIO execution](../audit/data/startup_init_emulation.json)
generated by [the reproducer](../audit/tools/emulate_startup_init.py). The
emulator executes original bytes with an ARM926 instruction surrogate; it does
not model clock settling, flash, interrupts, or the installed board.

With a locally obtained image of the stated hash and Unicorn installed, regenerate
the bounded execution artifact with:

```sh
python audit/tools/emulate_startup_init.py firmware_v2.8.4HF.bin --output audit/data/startup_init_emulation.json
```

## ARM vectors and reset path

The seven ARM branch words at `0x4000..0x401C` dispatch reset to `0x4044`,
five exception vectors to `0x40EC`, and IRQ to `0x4090`. FIQ continues at
`0x401C`; its body uses the banked FIQ registers and an AIC handler pointer.
The IRQ body at `0x4090..0x40E0` saves exception state, calls the AIC-selected
handler, acknowledges the interrupt, and restores status. The five-vector
fallback at `0x40EC..0x40F8` calls the reset-request helper at `0x7434`.
These are instruction-level paths; nested timing and the result of a reset
request remain unmeasured. The [earlier exception review](STARTUP_PERSISTENCE_REVIEW.md)
provides the register sequence.

The ARM reset body at `0x4044..0x408C` sets an initial stack, enters Thumb
`0x414C` for hardware setup, prepares FIQ and IRQ banked state, switches to
supervisor mode, calls Thumb `0x4114` for memory descriptors, and jumps to
Thumb `0x77B8`. LR is loaded with `0x408C`, a self-loop if that continuation
returns. `0x40E0`, `0x40E4`, and `0x40E8` are also one-instruction self-loops
used as fallback AIC targets. None is treated as an ordinary returning
function. Literal words at `0x40F8..0x4114` supply the stack, mode-switch
targets, AIC base and continuation addresses.

## Three memory descriptors

The Thumb loop at `0x4114..0x4144` reads three 12-byte records in
`0x96C4..0x96E8`. When source and destination differ, it calls forward byte
copy helper `0x8530`; when they match, it passes fill byte zero to `0x854C`.
The `0x854C..0x8562` routine narrows R1 to a byte, writes it R2 times from
R0, and returns with the original R0 and a depleted R2. It does not check
destination bounds. The two loop bounds at `0x4144..0x414C` are literal data.

The bounded execution used empty synthetic SRAM and checked the exact outputs:

| Operation | Bytes | Destination | Source or fill |
|---|---:|---|---|
| Initialized data copy | 2,208 | `0x200000` | image `0x96E8` |
| Zero fill | 994 | `0x2008A0` | zero |
| Executable helper copy | 164 | `0x200C84` | image `0xB114` |

It visited all 46 decoded starts across the descriptor loop and its two copy
helpers. This tests byte effects for these synthetic initial conditions;
physical SRAM size, overlap behavior outside these descriptors, and later
mutations require separate evidence.

## Peripheral and master-clock setup

`0x414C..0x41BE` made the following relevant 32-bit writes in the bounded
execution with synthetic PMC status bits 0, 2 and 3 already ready:

| Address | Value | Supported register reading |
|---|---:|---|
| `0xFFFFFF60` | `0x00000100` | flash mode register write; field effect not measured |
| `0xFFFFFD44` | `0x00008000` | watchdog mode register, WDDIS set |
| `0xFFFFFC20` | `0x00000601` | main oscillator enabled, OSCOUNT 6 |
| `0xFFFFFC2C` | `0x00481C0E` | PLL: DIV 14, PLLCOUNT 28, MUL 72 |
| `0xFFFFFC30` | `0x00000004`, then `0x00000007` | master-clock prescaler /2, then PLL selected |

The helper polls PMC status bit 0 for oscillator stability, bit 2 for PLL lock,
and bit 3 after each master-clock register update. With ready flags forced
true, all 57 decoded starts were visited. A nonsettling oscillator or PLL
would keep it in a wait loop; no timeout or failure branch is visible in this
range. The helper also installs fallback AIC vector 0 as `0x40E0`, vectors
1–30 as `0x40E4`, and the spurious-interrupt vector as `0x40E8`.

The [SAM7S clock register definitions](https://ww1.microchip.com/downloads/en/DeviceDoc/doc6175.pdf)
give `PLL = crystal × (MUL+1) / DIV` and master clock `MCK = PLL / 2` for
the final register value. Thus this image requests `MCK = crystal × 73 / 28`.
If the user's V2.2 MCU crystal marking `18.4` means exactly 18.400 MHz,
the implied MCK is about **47.971 MHz**. If its nominal frequency is
18.432 MHz, the implied MCK is about **48.055 MHz**. These numbers depend on
the actual crystal, successful PLL lock, and successful clock switching.
They are calculated settings, not measured frequency. The separate
provisionally 16 MHz crystal by the MCP2515 does not enter this calculation.
The ADC prescaler reviewed in [ADC initialization](ADC_INIT_VECTOR_REVIEW.md)
would produce `ADCClock = MCK / 22`, about 2.18 MHz under either MCU-crystal
example; ADC clock and analog timing remain unmeasured.

The halfword `0x41BE..0x41C0` is a Thumb NOP before 12 literal words at
`0x41C0..0x41F0`. The byte ledger records these separately from the
`0x414C..0x41BE` instruction body. No device traffic or firmware write was
performed for this review.
